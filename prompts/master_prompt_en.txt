You are a code agent with access to a terminal (Bash) in this project —
whether Claude Code, Codex, opencode (with any model: DeepSeek, GLM,
Kimi, etc.) or similar. None of these instructions depend on which
agent or model you are — you only need to read/write files and
run Bash commands.

Your mission: create the FULL production package for a faceless YouTube
video in the animated curiosity channel style (like Whymentary), in the
TRANSPORTATION ENGINEERING niche, in English. FULLY AUTONOMOUS: never stop
to ask the user anything; from the topic to the final MP4, you complete
every step yourself.

CHANNEL FORMAT (non-negotiable):
ONE single transportation machine or system per video (plane, train, ship,
rocket, submarine, helicopter, car, crane, elevator...), explained in depth
for ~3 minutes. A DEEP DIVE into how it works, why it works, and where the
viewer meets it. Every image must be a CONCRETE, RECOGNIZABLE object — the
AI image model draws iconic machines (planes, trains, ships) extremely well
but FAILS at abstract diagrams (force vectors, torque, stress). So the
script must be written around VISIBLE, DRAWABLE things.

━━━ PART 0: PICK THE MACHINE ━━━
Generate 6 candidate machines/systems for a transportation-engineering
deep-dive channel in English. Each candidate must be ONE specific machine
or system that the viewer knows by sight:
- "How a jet engine turns fuel into thrust"
- "Why a submarine can dive and surface"
- "How a maglev train floats"
- "Why a cargo ship doesn't tip over"
- "How a helicopter hovers"
- "How a rocket steers in space"
- "Why a plane's wings have that shape"
- "How a bullet train corners at 300 km/h"
- "How a crane lifts a thousand tons"
- "Why a hovercraft rides on air"

The candidate must be: (a) explainable in ~500 words, (b) a machine the
viewer has SEEN (recognizable silhouette), (c) with at least one
surprising detail. AVOID anything requiring abstract diagrams (gear ratios,
force vectors, stress concentration) — the images must be drawable as a
plane/train/ship/etc. with the engineer nearby.

Evaluate the 6 candidates by: curiosity gap, deep-dive richness, and
VISUAL CONCRETENESS (can the image model draw the machine + a clear
situation in doodle style?). Auto-pick the best, mark it with ⭐, and
proceed without waiting. If the user already gave you a machine, use it.

━━━ PART 1: SCRIPT (TARGET: 3 MINUTES) ━━━
Write the full script in English. TARGET LENGTH: 450-550 words
(≈ 3 minutes of narration). Do NOT exceed 550 words.

Structure (deep dive into ONE machine):
• HOOK (12s): the most surprising question or fact. "I didn't know that"
  within 5 seconds.
• WHAT IT IS (20s): name the machine plainly, define it in one sentence
  anyone understands, say where the viewer meets it.
• HOW IT WORKS (60-75s): the mechanism, step by step, told through
  VISIBLE parts (wings, engines, propellers, ballast tanks, wheels).
  Explain jargon in plain language the first time it appears.
• WHY IT WORKS (30-45s): the physics/materials in ONE idea, connected to
  something visible ("the wing is curved so air above moves faster").
• REAL-LIFE MOMENTS (30-45s): 2-3 concrete places the viewer has seen it
  — the plane they flew on, the train they took.
• FINAL FACT + CTA (15s): the most impressive fact + open question for
  comments + like and subscribe.

Rules:
- Short sentences (8-12 words on average)
- Second-person narrative tone (you)
- No lists or bullets — continuous oral narration
- Concrete, comparable facts ("10 times stronger than", "a football field
  long")
- EVERY mechanism must be described through a visible, drawable part —
  never through abstract forces alone
- End the HOW/WHY sections with: "But what nobody expected is..."

━━━ PART 2: SPLIT INTO SCENES ━━━
Split the script into scenes of 4-8 seconds (~12-20 words each). Each
scene is ONE entry in project.json. The channel's visual identity is a
STICK-FIGURE ENGINEER wearing a BRIGHT YELLOW HARD HAT — he appears in
EVERY AI-generated image, reacting to or explaining the machine.

Choose the visual type for each scene (THREE TYPES):
- "still" (use for ~70% of scenes): a narrative AI image in the channel's
  MS-Paint doodle style, ALWAYS featuring the stick-figure engineer with
  his yellow hard hat and the MACHINE. USE FOR: the machine in its
  environment, the engineer inspecting it, real-life moments, humor.
  NEVER request text, labels or numbers inside the image — AI image
  models garble text.
- "diagram" (use for ~15% of scenes): a CODE-GENERATED diagram (rendered
  by Pillow, crisp perfect text — NOT an AI image). USE FOR: any
  technical moment that needs labels or structure: flow paths, part
  names, stages, comparisons, cross-sections with named parts. You write
  a declarative spec JSON: nodes (id + label) and edges (from/to +
  optional label), plus optional title. Keep it simple: 2-6 nodes, 1-6
  edges. Example spec:
    {"title": "Jet engine airflow", "nodes": [
      {"id": "fan", "label": "FAN"},
      {"id": "core", "label": "CORE"},
      {"id": "nozzle", "label": "NOZZLE"}],
     "edges": [
      {"from": "fan", "to": "core", "label": "air"},
      {"from": "core", "to": "nozzle", "label": "thrust"}]}
  The diagram file path goes in visual.spec (relative, like
  "diagrams/scene-003.json") — write the spec file too, under
  output/<slug>/diagrams/.
- "text-card" (use for ~15% of scenes): bold typographic card (Pillow,
  crisp text). USE FOR: the machine's name in the intro, key numbers,
  the final fact, section titles. Just provide visual.text (short, 2-6
  words per line, max ~4 lines).

DO NOT use "character" scenes, NEVER request text inside AI images, and
never put labels in a "still" prompt — labels/structure go in "diagram"
(code-generated) or "text-card" scenes.

━━━ IMAGE PROMPT RUBRIC (CRITICAL — every still prompt MUST follow
this structure, 100-160 words, NO TEXT IN THE IMAGE) ━━━
Write every visual.prompt as a precise scene description:
1. SHOT: "Wide shot" / "Medium shot" / "Close-up" — and what fills the center.
2. THE MACHINE: name it, its exact shape, color, size relative to the frame,
   where it sits (left/right/center, foreground/background). Describe it as
   a child would draw it: "a white passenger jet with two engines under the
   wings, seen from the side".
3. THE ENGINEER: what he is doing — exact pose and gesture ("points at the
   wing with his left arm raised", "kneels beside the landing gear holding
   a wrench"), his yellow hard hat always visible.
4. OBJECTS/DETAILS: every visible object with shape and color and position
   ("a small red fuel truck parked under the wing").
5. BACKGROUND: one line, simple ("empty runway, blue sky", "grey hangar").
6. MOOD: one word ("curious", "impressed", "surprised").
FORBIDDEN: any text, letters, numbers, labels or words inside the image —
the model garbles them. Anything textual goes in a text-card scene. NO
style words (MS Paint, stick figure, doodle) — the style is added
automatically. NO abstract arrows/forces/vectors as the subject. NO
technical cross-sections or labeled cutaways — keep scenes simple and
readable: one machine, one situation.

━━━ PART 3: WRITE project.json + script.txt ━━━
Create the folder output/<machine-slug>/ and write:
1. script.txt — the full narration text (plain text, no numbering).
2. project.json — array of scenes, each:
   {"index": N, "text": "<narration for this scene>",
    "visual": {"type": "...", ...type-specific fields...}}
   Follow schemas/project.schema.json exactly. index is 1-based, in order.
   Text cards: visual.text is the card text (may differ slightly from
   scene text — it's the ON-SCREEN text, keep it short).
   Stills/diagrams: visual.src like "04.png" (the file run_all.py will
   generate) + visual.prompt following the IMAGE PROMPT RUBRIC above.

━━━ PART 4: RUN THE PIPELINE ━━━
Run the single command that does EVERYTHING (images, narration, subtitles,
assembly):

    python scripts/run_all.py --dir output/<machine-slug> --lang en

If it fails, read the error, fix the cause (usually a missing visual field
or a bad prompt), and re-run. run_all.py is idempotent: finished assets
are kept, only what's missing gets (re)built. Images that fail validation
are regenerated automatically with an improved prompt.

Plus the video's word count (target 450-550), duration (should be ~3
